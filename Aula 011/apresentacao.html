O Problema do Provisionamento Manual

❌ Configuração manual e artesanal

  • Inconsistência (configuration drift)
  • Baixa reprodutibilidade
  • Erros humanos frequentes
  • Falta de documentação e auditoria
  • Escalabilidade limitada
"Na minha máquina funciona" ← o sintoma clássico do drift

Declarativa vs. Imperativa

✅ Declarativa

  • Descreve o ESTADO FINAL
  • Ferramenta decide o COMO
  • "Quero 3 servidores"
  • Terraform, CloudFormation
  • Simples, idempotente

⚠️ Imperativa

  • Descreve PASSO A PASSO
  • Foco no COMO fazer
  • "Crie A, depois B, depois C"
  • Scripts shell
  • Verboso, propenso a erros

Terraform

Ferramenta de IaC líder (HashiCorp):

  • Agnóstico ao provedor: HCL + providers → AWS, Azure, GCP, K8s
  • State file: rastreia código ↔ recursos reais
  • Multi-cloud: mesma linguagem para tudo
  • Declarativo: descreve o estado desejado
resource "aws_instance" "web" {
  ami           = "ami-0abc123"
  instance_type = "t3.micro"
  tags = { Name = "servidor-web" }
}

Fluxo de Trabalho do Terraform

1. terraform init    → Baixa providers
2. terraform plan    → Mostra mudanças (SEM aplicar)
3. [Revisão humana]  → Aprova as mudanças
4. terraform apply   → Aplica mudanças reais
5. terraform destroy → Remove tudo (temporários)
Diferencial de segurança: O plan mostra o impacto ANTES de tocar em produção.

Provisionamento vs. Configuração

🏗️ Provisionamento

Criar a infraestrutura

  • Terraform
  • CloudFormation
  • ARM / Bicep
  • Pulumi

🔧 Config. Management

Configurar o interior

  • Ansible
  • Chef
  • Puppet
Na prática: Terraform cria a infra + Ansible configura os servidores. Muitas vezes combinados.

IaC, CI/CD e GitOps

Commit no Git → Validação → terraform plan
   → Aprovação → terraform apply → Infra atualizada
GitOps = Git como fonte única de verdade
  • Toda mudança via pull request
  • Revisão, teste e auditoria automáticos
  • Ferramentas: GitHub Actions, GitLab CI, Atlantis, Terraform Cloud

Boas Práticas

  1. 🧩 Modularização — módulos reutilizáveis
  2. 🔒 Estado remoto e seguro — S3 + locking
  3. ♻️ Idempotência — mesma execução, mesmo resultado
  4. 🏗️ Infra imutável — substituir, não modificar
  5. 🗂️ Separar ambientes — dev, staging, prod
  6. 🔑 Nunca versionar segredos — Secrets Manager/Vault
  7. ✅ Revisão obrigatória — plan antes do apply
