Da Rede Física à Virtual

🔌 Rede Tradicional

  • Switches físicos, cabos, roteadores
  • Semanas para provisionar
  • Limitada ao hardware disponível

☁️ Rede em Nuvem (SDN)

  • Definida inteiramente por software
  • Provisionamento em segundos
  • Escalável e programável via API
Conceito-chave: A funcionalidade é idêntica — a implementação é radicalmente diferente.

VPC / VNet: Conceito

Virtual Private Cloud (VPC) — AWS, GCP | Virtual Network (VNet) — Azure

O que é: Rede virtual logicamente isolada dentro do provedor, com controle total do cliente.

Você controla:

  • Faixa de endereços IP
  • Segmentação em sub-redes
  • Tabelas de roteamento
  • Gateways de acesso
  • Políticas de segurança

Internet Gateway vs. NAT Gateway

🌐 Internet Gateway (IGW)

  • Comunicação bidirecional VPC ↔ Internet
  • Horizontalmente escalável e redundante
  • Anexado à VPC
  • Usado por sub-redes públicas

🔒 NAT Gateway

  • Saída privada → internet (unidirecional)
  • Posicionado na sub-rede pública
  • Traduz IP privado → IP público na saída
  • Bloqueia conexões iniciadas externamente

VPC Peering

Conceito: Conexão direta entre duas VPCs

  • Tráfego privado (não passa pela internet)
  • Não transitivo (A↔B + B↔C ≠ A↔C)
  • Pode ser entre contas ou regiões diferentes
  • Requer atualização das route tables em ambos os lados
Limitação: Em N VPCs, precisa de N×(N-1)/2 peerings — não escala bem.
🔗
12 / 15

Transit Gateway

Conceito: Hub centralizado para conectividade multi-VPC

Características:

  • Topologia hub-and-spoke (estrela)
  • Roteamento transitivo funciona
  • Conecta VPCs + VPNs + Direct Connect
  • Suporta dezenas de redes

Quando usar:

  • 3+ VPCs que precisam se comunicar
  • Conectividade híbrida (on-premises)
  • Centralização de roteamento
🕸️

Resumo

Conceitos-chave:
  • VPC/VNet = rede virtual isolada, totalmente controlada pelo cliente
  • CIDR define o espaço de endereçamento (planeje antes de criar!)
  • Sub-redes públicas → IGW; privadas → NAT Gateway
  • Security Groups (stateful, instância) + NACLs (stateless, sub-rede)
  • VPC Peering (ponto-a-ponto) vs. Transit Gateway (hub centralizado)
