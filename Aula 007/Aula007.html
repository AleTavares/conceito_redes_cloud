Well-Architected Framework

5 Pilares fundamentais:

PilarFoco
⚙️ Excelência OperacionalExecutar, monitorar, melhorar
🔒 SegurançaProteger dados e sistemas
🔄 ConfiabilidadeRecuperar de falhas
⚡ Eficiência de PerformanceUso eficiente de recursos
💰 Otimização de CustosEntregar valor pelo menor custo

Toda decisão arquitetural é um trade-off entre pilares.

Microsserviços vs. Monolito

📦 Monolito

  • Uma unidade de deploy
  • Simples inicialmente
  • Escala uniforme
  • Ideal para MVPs

🧩 Microsserviços

  • Serviços independentes
  • Deploy/escala separados
  • Database per service
  • Ideal para escala
Regra de ouro: Comece monolítico, evolua para microsserviços quando a escala exigir.

Arquitetura Serverless

Usuário → API Gateway → Lambda → DynamoDB
               ↓
        EventBridge → Lambda → S3
               ↓
             SQS → Lambda → SNS

✅ Vantagens

  • Zero gerenciamento
  • Custo zero quando idle
  • Auto scaling por evento

⚠️ Limitações

  • Cold start
  • Max 15 min/execução
  • Vendor lock-in

Alta Disponibilidade Multi-AZ

     ┌──── AZ-a ────┐   ┌──── AZ-b ────┐
     │  EC2 (ASG)    │   │  EC2 (ASG)    │
     │  RDS Primary  │   │  RDS Standby  │
     │  NAT Gateway  │   │  NAT Gateway  │
     └───────────────┘   └───────────────┘
          ↕ failover automático ↕

Elementos-chave:

  • Load Balancer cross-AZ
  • Auto Scaling distribuído em 2+ AZs
  • RDS Multi-AZ (failover < 60s)
  • NAT Gateway por AZ

Escalabilidade e Auto Scaling

TipoDescriçãoLimite
Vertical (Scale Up)Aumentar recursos da instânciaMaior tipo disponível
Horizontal (Scale Out)Adicionar mais instânciasIlimitado (teórico)

Políticas de Auto Scaling:

  • Target Tracking: Manter CPU média em 60%
  • Step Scaling: +2 instâncias se CPU > 80%
  • Scheduled: Mais capacidade em horário comercial
  • Predictive: ML prevê demanda futura

Resumo

Padrões arquiteturais para nuvem:
  • Well-Architected: 5 pilares guiam toda decisão
  • Three-Tier: separação por responsabilidade
  • Microsserviços: independência e escalabilidade granular
  • Serverless: zero gerenciamento, custo por execução
  • Event-Driven: desacoplamento e resiliência
  • Multi-AZ + Auto Scaling: alta disponibilidade
