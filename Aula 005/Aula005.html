O que é Nuvem Híbrida?

Definição NIST: Composição de 2+ infraestruturas de nuvem distintas (privada + pública) interligadas por tecnologia que permite portabilidade de dados e aplicações.

Elemento-chave: Integração orquestrada (não é apenas "ter os dois")

Componentes:

  • Datacenter on-premises ou nuvem privada
  • Uma ou mais nuvens públicas
  • Conectividade dedicada (VPN, Direct Connect, ExpressRoute)
  • Plano de gestão unificado

Padrão: Cloud Bursting

Conceito: Capacidade local + elasticidade da nuvem pública sob demanda

Como funciona:

  • 1️⃣ Carga normal → processada no datacenter privado
  • 2️⃣ Pico de demanda → excedente "transborda" para nuvem pública
  • 3️⃣ Demanda normaliza → recursos públicos liberados automaticamente
Benefício: Dimensionar o datacenter para a carga média, não para o pico.

Padrões: Tiered Deployment e DR

📊 Tiered Deployment

  • Camada sensível (dados, compliance) → Privada
  • Camada web, analytics, dev/test → Pública

🛡️ Disaster Recovery na Nuvem

  • Site primário: on-premises
  • Site de DR: nuvem pública (custo reduzido)
  • RPO/RTO definidos conforme criticidade

O que é Multi-cloud?

Definição: Utilização simultânea de 2+ provedores de nuvem PÚBLICA

Diferença fundamental da híbrida:

  • Multi-cloud = público + público
  • Híbrida = privado + público

Exemplo:

  • Machine Learning → Google Cloud (Vertex AI)
  • Infraestrutura geral → AWS (EC2, S3)
  • Identidade/Office → Azure (AD, Microsoft 365)

Desafios: Complexidade e Custos

⚠️ Desafios operacionais

  • Equipe precisa dominar múltiplas plataformas
  • Governança de segurança inconsistente
  • Observabilidade fragmentada
  • Maior superfície de ataque

💸 Custos ocultos

  • Egress costs (transferência entre nuvens)
  • Ferramentas de gestão adicionais
  • Treinamento e certificações múltiplas
  • Complexidade em contratos e billing
⚠️
9 / 16

Vendor Lock-in

O que é: Dependência de serviços proprietários que dificulta migração

Como se proteger:

  • ✅ Usar containers (Docker) para portabilidade
  • ✅ Kubernetes para orquestração agnóstica
  • ✅ Terraform para IaC multi-provedor
  • ✅ APIs padronizadas e protocolos abertos
  • ✅ Avaliar exit strategy antes de adotar serviços proprietários
Trade-off: Portabilidade total ↔ Funcionalidades nativas avançadas

Casos de Uso Reais

🎬 Streaming (Multi-cloud)

  • CDN → Cloudflare
  • Compute → AWS
  • AI/ML → Google Cloud

🏥 Hospital (Híbrida)

  • Prontuários → Nuvem privada (LGPD)
  • Analytics/BI → Azure

🛒 Varejo (Híbrida + Multi-cloud)

  • ERP legado → On-premises
  • E-commerce → AWS
  • Pagamentos → Azure (compliance PCI)

Resumo

Pontos-chave:
  • Nuvem Híbrida = integração orquestrada entre privado e público
  • Multi-cloud = múltiplos provedores públicos simultaneamente
  • Cloud bursting, tiered deployment e DR são padrões híbridos fundamentais
  • Vendor lock-in é mitigado com containers, K8s e IaC agnóstica
  • Egress costs são o custo oculto mais subestimado
  • A escolha depende de requisitos de compliance, custo e resiliência
